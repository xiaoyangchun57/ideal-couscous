# 人本可用性测试包

适用范围：本地后端 `http://127.0.0.1:5000`、Web 管理端 `http://127.0.0.1:5174`、微信开发者工具模拟器。首轮用于建立体验基线，不发布、不写入生产环境。

## 使用顺序

1. 主持人准备三个角色账号、可重复使用的测试站点和测试照片；执行前记录当前数据库快照或测试数据编号。
2. 每名参与者独立完成其角色任务卡。主持人只能读任务卡，不能解释菜单、按钮或业务规则。
3. 参与者全程说出正在想什么；主持人填写 `session-record.md`，截图或录屏仅保存到本地测试证据目录。
4. 每项任务结束询问："你以为会发生什么？哪里不确定？你敢在真实工作中这样提交吗？"
5. 完成全部任务后填写 SUS 问卷；主持人把问题写入 `issue-log.csv`，按 P0-P3 分级。
6. 修复后必须使用原任务卡复测，更新台账的修复版本、复测结果和残留风险。

## 规则

- 参与者：至少 2 名运维人员、1 名管理员、1 名审核员，优先真实业务人员。
- 每项任务的结果只能标记为：独立完成、完成但犹豫、需提示完成、失败、产生错误数据。
- P0/P1 必须在下一轮之前修复并复测；P2/P3 进入按影响和频率排序的优化池。
- 不记录密码、令牌、手机号、精确定位或未经许可的个人影像。
- 模拟器不能替代真机。真机定位、相册授权、弱网和机型差异必须在第二轮单独验证。

## 交付物

- `task-cards.md`：不泄露操作路径的角色任务卡。
- `session-record.md`：每位参与者一份观察记录。
- `issue-log.csv`：可汇总、排序和复测的问题台账模板。
- `sus-questionnaire.md`：标准 SUS 问卷和基线计算规则。

## 统一观察项

每个任务都观察：用户是否知道自己在哪里、下一步是什么、提交后会发生什么；是否理解状态、权限、照片、定位和网络限制；失败后能否自主恢复；返回、刷新或弱网后是否丢失上下文或重复写入。

视觉交互同时观察：三秒内能否识别主任务和风险；文字/按钮是否清晰可读可点；主次操作是否分明；颜色是否搭配文字和图标；加载、成功、失败、待同步是否即时且明确；空状态是否给出下一步；跨端状态是否一致。
