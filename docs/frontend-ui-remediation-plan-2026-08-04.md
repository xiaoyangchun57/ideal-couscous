## 3. B0-A：权限与会话止血

### 修复策略

- 建立唯一的后端授权策略：`admin`、`operator`、`reviewer` 按角色集合判定，前端隐藏菜单只负责体验，不再承担安全职责。
- 将“管理员无限范围”和“运维人员未分站”拆成不同数据状态；运维人员空 `site_ids` 必须解释为零站点，不得解释为全站。
- 所有站点档案、设备、车辆、影像、数据源、阈值、工单创建接口统一调用角色与站点范围校验。
- 将内存 token 改为可撤销会话：保存 token 哈希、用户、签发时间、到期时间、撤销时间和 `auth_version`；退出、停用、注销、密码重置均撤销相关会话。
- 密码重置改为随机一次性临时密码或管理员设置的新密码；首次登录强制改密，不再使用固定公开值。

### 数据迁移与依赖

- 新增 `auth_sessions`（或等价表）和 `users.auth_version / must_change_password`；部署迁移时使现有 token 全部失效，避免旧会话绕过新模型。
- 对 `user_sites` 建唯一约束；检查并人工确认现有空站点运维账号，不自动授予全站。
- 权限中间件必须先落地，再开放 B0-B 的数据源、影像和审核接口。

### 验收

- 管理员、单一运维、单一审核员、双角色四种账号执行路由和接口矩阵；未授权读取与写入均返回明确 403。
- 运维账号只能读取绑定站点；未分站运维返回空范围和可理解空状态。
- 退出、停用、重置密码后，用旧 token 请求 `/api/auth/me` 和任一业务接口均为 401。
- 影像跨站读取、修改、归档、删除以及伪造归档人全部被拒绝，并写安全审计日志。

## 5. B1-A：请求契约、事务与防重复

### 修复策略

- 分阶段重构 `react-vite/src/services/api.js`：先增加严格调用族，所有非 2xx 和网络错误抛出统一 `ApiError`，包含状态码、业务消息、请求 ID 和是否可重试；旧调用暂时保持兼容，直至逐批迁移完毕。
- 逐批迁移调用点：读取页具有 `loading / error / empty / ready` 四态；写操作只在明确成功响应后关闭弹窗和提示成功。每批独立构建和断网复测，避免共享契约一次切换造成连锁回归。
- 所有提交按钮增加提交锁；关键创建接口接收幂等键，数据库增加与业务语义一致的唯一约束。
- 业务记录与证据上传采用事务或“两阶段状态”：先保持“待补传/部分成功”，允许补传和重试，不能在照片失败时宣告整单完成。
- 登录加入账号与 IP 维度的渐进退避、限速和安全日志；不依赖验证码作为唯一防护。

### 数据迁移与依赖

- 新增请求幂等记录或业务唯一键；阈值规则、试剂更换历史和车辆记录先查重，再建立约束，避免迁移失败。

- 共享 API 契约变更影响面大，必须先加封装层单元测试，再逐页迁移，禁止新旧返回语义长期并存。
