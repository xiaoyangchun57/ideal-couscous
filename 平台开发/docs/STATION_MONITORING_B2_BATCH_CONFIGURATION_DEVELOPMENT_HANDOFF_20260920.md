> 状态：`PRODUCT_BLOCKED / WAITING_STATION_MASTER_REFRESH`
> 当前责任人：产品侧更新站点主数据
> 开发停点：不得继续应用身份、配置、迁移、重放、提交或部署

## 当前产品决定

现有站点清单同时存在简称、旧别名、失效站和新增站，继续逐站修补会反复返工。数据接入实现暂停，等待产品侧统一更新一版站点主数据后再做一次批量匹配。

恢复后的首要目标是让有效站点能够正常接收、解析、匹配和展示数据。经纬度及其余档案信息允许后续维护，不作为首轮接入门禁。

## 恢复所需最小信息

每个站点尽量提供：

- 当前正式站点名称；
- 原平台 MN；
- 是否继续有效；
- 已知旧名称或别名，可为空。

经纬度、地址、责任人、仪器和其他档案字段不要求本轮一次补齐。

## 批量匹配口径

1. 以 MN 精确匹配作为第一身份依据；MN 相同不得因名称差异阻断。
2. 名称只做规范化和别名辅助匹配，不把简称、全称差异直接判为硬错误。
3. MN 缺失、重复，或一个 MN 指向多个有效站点时才列为需人工拍板项。
4. 可唯一判断的站点先形成接入配置；少量未匹配、未知因子或档案不完整项集中列出，不阻断其他站点。
5. 不使用经纬度决定数据身份。坐标不准确的站点先接入数据，后续由现场人员在站点详情中校准位置。
6. 其他站点资料沿用现有值或留空，后续通过管理端逐步维护。

## 旧站与失效站

- 已确认失效的站点退出当前有效目录和新数据投影，不再要求形成新观测。
- 既有原始报文、历史观测、巡检记录和审计事实继续保留，不物理删除。
- 旧名称作为历史别名保留，仅用于识别历史数据，不生成第二个有效站点。

## 恢复后的最短顺序

1. 只读预览新站点清单，输出“精确匹配 / 别名辅助匹配 / 失效 / 需拍板”四组。
2. 产品只处理重复 MN、缺失 MN 和多站歧义；其他资料缺失不阻断。
3. 在已验收基线上适配新的 MN 优先批量匹配口径并跑隔离回归。
4. 产品代码 Review 通过后，再单独授权生产迁移、身份应用、配置和有限重放。

当前不建立候选、不提交、不部署、不操作生产数据库或接收器。
