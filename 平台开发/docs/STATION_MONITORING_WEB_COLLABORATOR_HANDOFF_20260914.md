## 1. 先了解项目

这是一个水质运维系统，包含 Web 管理端和微信小程序现场端。Web 端服务管理者和审核/运营角色，负责站点台账、数据接入观察、告警、工单、计划和档案管理；小程序服务现场人员，负责巡检、现场上报、整改、车辆等执行动作。

本次协作只做 Web 的“站点监测观察”部分，不接管接收器或现场业务。产品目标不是做复杂分析，而是让管理者知道：

- 哪些业务站点已经绑定监测身份；
- 身份是否收到认证原文；
- 监测档案、因子和周期是否已配置；
- 是否已经形成可信有效观测；
- 问题位于通信、到报、配置、数据质量还是业务跟进。

既有站点管理仍必须可用：站点创建、导入、档案编辑、试剂库存、负责人筛选和旧档案查看不能因新增监测页面丢失。

## 2. 数据链和术语

生产数据链的责任顺序是：

`站点 RTU -> HJ212 TCP 接收 -> trusted_endpoints 身份识别 -> ingest_raw_frames 原文留存 -> 规范化 observation_batches -> 有效 observation_values -> 站点监测只读投影 -> Web/小程序展示`

### B1 与 B2

- **B1 身份/原文事实**：站点 MN 与系统身份绑定、认证是否成功、原文是否收到。B1 只能证明通信和原文到达，不能证明水质值可发布。
- **B2 监测档案**：逐站因子映射、单位、周期、容忍时间、仪器资产和有效观测规则。B2 未批准时不显示数值、趋势、正常、超限或设备健康结论。

页面必须区分以下状态，不能合并成“在线/异常”：

`未接入`、`等待首帧`、`原文已收/档案待批准`、`等待首个有效观测`、`周期未配置`、`正常`、`需关注`、`数据暂不可用`。

“最后通信”是认证原文接收时间；“最后有效观测”是有效观测时间，两者不可互相替代。补传旧数据也不能显示成刚刚更新。

## 3. 角色和权限

- `admin`：可看全部有权站点，可看脱敏的接入中心摘要。
- `reviewer`：可看有权站点和监测结果，不可看接入治理摘要、身份、MN、PW、完整原文或控制动作。
- `operator`：按现有站点/组织范围使用既有运营功能；是否能看监测目录以服务端权限为准，不能由前端自行放大。

服务端是权限和数据范围最终权威。Web 只能消费投影，不解析协议、不读取凭据、不自行判断站点是否在线。
