## 1. 业务目标

数据接收链已经形成 B1 身份/原文事实，Web 需要让管理者回答：哪些站点已接入、原文是否到达、监测档案是否就绪、是否已有可信有效观测、问题属于哪一层。B2 档案/因子/周期未齐时，不展示假数值、假趋势、在线或水质结论。

既有站点管理仍必须可用：站点创建、导入、档案编辑、试剂库存、负责人筛选和旧档案查看不能因新增监测页面丢失。

## 4. 必须完成的 Web 工作

1. **站点目录**：站点名为第一识别层；监测状态必须使用独立字段，不覆盖旧站点业务状态。至少能表达未接入、等待首帧、原文已收/档案待批准、等待首个有效观测、周期未配置、正常、需关注和读取失败。
2. **站点详情**：保留返回、直达和刷新；按契约展示状态主原因、最后通信、最后有效观测、有效值、趋势能力、通信/数据/RTU/仪器分轴及近期事项。没有事实时显示明确空态，不用“未配置”掩盖所有原因。
3. **接入中心**：只给管理员可见且可进入；在 Web 中有明确入口。不得展示 MN、PW、完整原文或控制动作。审核员不能出现“页面可进、接口 403”的断链。
4. **上游跳转**：驾驶舱、告警、全局搜索等站点入口要明确区分“监测详情”和“档案管理”。不得让用户只能通过直接输入 `/sites/:siteId` 才能进入新模块。
5. **失败和刷新**：首次加载失败提供原位重试；刷新失败保留上次成功内容并标记失败；不能回退到旧档案、现场任务或客户端缓存来冒充监测结果。
6. **数据边界**：周期未配置时仍展示已形成的有效值及观测时间，但不做新鲜度判断；趋势只有存在对应聚合事实时才显示可用。客户端不得自行计算阈值、在线状态或设备健康。

## 5. 不可变边界

- 不把身份接入、监测档案、有效观测、设备健康和业务处置合并成一个标签。
- 不删除或改写既有站点管理能力。
- 不新增假数据、静态趋势、客户端阈值或“有值即设备正常”的推断。
- 不处理生产部署、真实数据、私有凭据或站点身份配置。
- UI 视觉可沿用现有 Web 设计系统；本交接只限定信息责任和范围，不限制具体组件形式。

## 6. 验收与回传

必须运行 React 相关测试、lint、build，并补充站点目录/详情/接入中心的直接测试，至少覆盖：管理员与非管理员、站点越权、八类状态、首次失败、刷新保留旧结果、旧档案入口保留、上游精确跳转和无聚合趋势空态。

回传内容只需包含：修改文件、测试结果、路由/权限变化、服务端字段依赖、仍被后端阻断的事项和下一步建议。不要提交、冻结或部署；真实 Web UI 验收另行执行。
