## 缺口与接口合同

- 端点：`POST /api/weekly-plans`，`平台开发/backend/app.py` 的 `api_weekly_plans_create`。可复现请求形状（管理员身份、隔离库）：`{"user_id":999999,"week_start":"2026-09-28","plan_data":{},"submit":false}`；再分别以停用账号、已注销账号的实际 ID 代替 `999999`。
- 已确认的**代码路径**：参数可转换为整数且管理员有权提交时，接口校验日期、站点后直接 `INSERT INTO weekly_inspection_plans`；没有查询目标 `users` 的存在性、`status`、`deleted_at`。从代码看可能返回 `201` 并留下记录，但这不是已实测的 HTTP 响应：**修复前实际响应及新增记录数由 C 用直接 API 测试记录**，不得将推断写为实测。
- 期望：在任何插入或车辆申请前，于服务端读取目标用户；不存在返回 `404` + 稳定 `code=PLAN_EXECUTION_USER_NOT_FOUND`，停用或 `deleted_at` 非空返回 `409` + 稳定 `code=PLAN_EXECUTION_USER_INACTIVE`（含可读 `error`）。与当前 `plan-schedules` 执行人校验的错误码语义对齐；`status='active'` 但 `deleted_at` 非空也必须拒绝。无效 `user_id` 仍为参数错误，非管理员给他人创建仍为 `403`，不得因新校验泄露额外账号信息或放宽权限。
- 校验和写入使用同一数据库连接及写入事务，避免查询后账号状态变化导致竞态；不删改已有周计划、历史用户名或注销审计。旧周计划页面本轮已取消异步候选 `initialValue`，不要因本任务重新接线旧页面或修改 Web 候选逻辑。
