## 实际 UI 场景与判定

1. 小程序：首页站点/试剂入口的一次性目标消费；无目标保留原模式、范围和筛选；管理员本人/全部及搜索，普通用户仅本人授权站点，详情与返回路径正确。
2. 监测：有效观测、等待首帧、收到报文但无有效观测、无数据、403 门禁与加载失败。先成功再 403 再档案回退失败时，不得出现旧监测字段；失败可见可重试。不得把报文到达、有效观测、设备及仪器健康混作同一状态。
3. 试剂：跨站总览、原因筛选、服务端允许动作、401/403 时清除旧列表和维护 Sheet；更换/标定失败保持输入及幂等键，重复点击无重复事实。标定值不用库存单位；通过标定不宣称全部正常；选择报修不冒称已建工单。
4. Web：站点监测/档案入口、权限、库存删除二次确认与原因（非空、最多 200 字）、失败原键重试、重复点击阻断、成功后刷新及刷新失败可见。至少从真实浏览器登录走到站点页面，不能用静态 200 页面代替。
5. 覆盖加载、空态、长内容、错误、禁用及 375×812、360×800 等效视口。每个缺少可信隔离数据的场景都标 `NOT RUN + 原因`，不能凭旧截图或夹具写 `PASS`。
