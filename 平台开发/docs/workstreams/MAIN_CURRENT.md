## 1. 主线使命

主线负责让各领域可以独立推进而不分裂成多个系统：维护公共权限、审批、消息、审计和导航，裁决跨域契约，管理写入冲突，完成集成 Review，并把通过验收的唯一提交交给冻结与发布流程。

主线不是所有功能的默认接线人，也不替领域负责人维护问题池。领域负责人对本域完整结果负责，主线只在公共能力、跨域冲突、高风险变更和最终集成时介入。

## 2. 核心链路

- 身份与权限：`登录/会话 → 角色与站点范围 → 页面和服务端能力 → 注销/移交 → 审计`
- 审批与消息：`业务事件 → 待办/通知 → 精确目标 → 决策 → 当前/历史归档 → 微信订阅`
- 公共体验：`首页/我的/全局导航 → 领域入口 → 返回与状态同步 → 更新提示`
- 版本集成：`领域 PR → 跨域 Review → 真实 UI → 唯一候选 → 独立发布任务`

## 3. 代码与验证地图

- 后端：`平台开发/backend/app.py` 中认证、用户、审批、通知、审计和公共首页接口。
- Web：`react-vite/src/pages/users/`、`audit/` 及公共路由、认证和搜索能力。
- 小程序：`app.js`、`app.json`、`pages/index/`、`mine/`、`message/`、`review/` 和公共工具。
- 协作与发布：`平台开发/docs/workstreams/`、候选清单、冻结和发布交接。
- 重点测试：认证恢复、用户权限、消息未读、审核定位、首页状态、全局导航和版本更新。

## 4. 不可变规则

- 服务端是权限、数据范围、状态迁移和有效数量的最终权威。
- 公共权限、消息和审计变更必须核对所有角色和业务来源，不能只修一个入口。
- 一项变更只有一个结果负责人；同一文件同一时间只有一个活动写入者。
- 合并、代码 Review、设计 Review、真实 UI、冻结和部署是不同状态。
- `main` 是共享开发基线，不自动等于发布候选。
- 生产操作、标签、发布和不可逆数据动作仍需用户明确授权并交独立发布任务。

## 5. 主线如何支持领域自治

- 维护共同工作制度和公共契约，不逐项给负责人传递上下文。
- 跨域需求只确认结果负责人、受影响领域、契约 Reviewer 和临时写入权。
- 领域内低风险事项由负责人自行启动；主线抽查，不形成审批瓶颈。
- 前两轮领域接管成果全部 Review，确认负责人能独立分析、实现和回传后再转为风险抽查。
- 发现重叠时先调整写入权或顺序，不让用户充当 A/B/C 的消息中转。

## 6. 设计支持

设计师在本地主线工作树中提供支持，不进入远程协作者矩阵：

1. 领域负责人提交产品骨架、状态和不可变边界。
2. 主线安排设计师在明确 UI 范围内完成静态方案并做静态 Review。
3. 主线把设计基线纳入共享仓库，领域结果负责人自行完成业务接线。
4. 可运行后设计师复核实际渲染，独立 UI 验收判断行为。
