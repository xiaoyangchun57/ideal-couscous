# 小程序真实 UI 集成返修产品协调输入

> 状态：`PRODUCT_COORDINATION_INPUT_ONLY`。本文件只记录产品范围和分工输入，不是开发或设计执行合同，不授予任何文件写入权。每项实施必须由唯一产品台账另行指定一份自包含交接；不授权合并、冻结或部署。

## 共同规则

- 每个结果负责人可建立本领域的专业设计师 Agent；业务代码仍由自包含交接授权的开发经理作为唯一写入者。新布局、信息层级、组件结构和图标方案必须先由本领域设计师 Agent 形成基线。
- 设计未完成的结构性问题标记 `DESIGN_REQUIRED`，不得自行试做一版。
- Web 真实 UI已通过。本文件只处理小程序；隔离验收使用的 BOM 临时补丁不等于正式代码已修复。
- 下列 A/B/主线内容是后续交接的产品输入；在交接补齐唯一写入者、精确文件、输入契约、测试和停点之前不得执行。

## 主线

主线领域后续交接应覆盖公共 TabBar 图标、公共页头固定与安全区、动态 sticky 高度契约、首页运维概览、首页试剂分类计数和管理员站点范围文案，并禁止修改 A/B 业务文件。

## A：站点与试剂

A 的设计交接应覆盖站点/试剂一级模式与二级筛选层级、试剂卡片、登记更换/完成标定弹窗的静态方案。后续开发交接可包含文件头 BOM、Sheet 与原生 TabBar、失败输入和幂等键，以及设计交付后的筛选、卡片、弹窗、长内容和动态 sticky 接线；必须明确精确允许文件，并禁止修改首页、公共 TabBar、公共导航组件和试剂后端。

正式交接的回传至少包含分支与不可变 SHA、文件清单、采用的设计基线、自动测试、微信开发者工具编译和真实 UI 状态；强制停点为主线 Review，不合并、不部署。

## B：巡检计划

“常用计划”当前前后端均只允许 `operator`，因此管理员只能看到“新建计划”。产品口径候选为：具备计划创建能力的 `admin` 与 `operator` 均可使用自己的常用计划；`reviewer` 不因审核角色自动获得。PR #4 收口后，产品主线须另行形成自包含交接，写清唯一开发写入者、前后端精确文件、权限契约及成功/越权/他人数据测试，不能只恢复按钮。

未经该交接不得混入 PR #4、修改代码或扩展其他计划权限。

## C

本轮无写入任务。试剂接口已返回 `status_counts`，首页显示为 0 是主线消费映射遗漏；除非主线提出契约争议，C 保持只读支持。
