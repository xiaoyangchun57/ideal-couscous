# 页面设计自检清单

> 做完一个页面后，按对应类型逐项检查。
> 每项都有明确的"对/错"判断，不是主观感受。

---

## 通用检查（所有页面都要过）

### Token 合规
- [ ] 页面 WXSS 中没有硬编码 hex 色值（grep `#` 不出现颜色值）
- [ ] 所有颜色都通过 `var(--color-*)` 语义 Token 消费
- [ ] 间距值都是 2 的倍数，优先使用 `--space-*` 系列
- [ ] 圆角使用 `--radius-*` Token，不写死 `15px` 等非标值

### 视觉一致性
- [ ] 页面背景色是 `--color-background`（灰底 `#F2F2F7`）
- [ ] 卡片白底 `--color-card`，圆角 `--radius-xl`（16px），且没有卡片嵌套卡片
- [ ] 卡片左右边距 16px，卡片间距 10px
- [ ] 文字层级正确：主文字 `--color-text-primary`，二级 `--color-text-secondary`，三级 `--color-text-tertiary`
- [ ] 没有"业务类型用彩色标签"的情况（违反铁律第 1 条）

### 小程序适配
- [ ] 自定义导航栏适配了状态栏高度（`--wx-status-bar-height`）
- [ ] 标题没有被右侧胶囊按钮遮挡
- [ ] Tab 页底部留了 TabBar 高度 + 安全区的内边距
- [ ] 底部固定按钮适配了 `env(safe-area-inset-bottom)`

---

## 列表页检查

### 导航与筛选
- [ ] 导航栏样式正确（Tab 根页用大标题 + 自定义导航栏；二级页用原生导航栏）
- [ ] 筛选用 Segmented Control（≤4 个选项）或筛选面板，不用彩色 Tab
- [ ] 搜索栏样式统一（如有）

### 列表内容
- [ ] Section 标题：13px、三级文字色、上间距 20px、下间距 6px
- [ ] 列表行最小高度 44px，长内容可增高；左侧图标 18px，右侧箭头颜色正确
- [ ] 分隔线从左侧 16px 处开始（不是整宽）
- [ ] 状态标签用对了颜色（查铁律第 2 条）
- [ ] 状态标签是胶囊形，尺寸 11px 字 + 上下 2px + 左右 8px

### 空状态
- [ ] 无数据且可主动添加：显示空状态 + 添加按钮
- [ ] 搜索无结果：显示空状态，无按钮
- [ ] 加载失败：显示空状态 + 重新加载按钮
- [ ] 无权限：显示空状态，无操作按钮

---

## 表单页检查

### 字段布局
- [ ] 字段标签在上，输入框在下
- [ ] 必填项用红星标记（`*`）
- [ ] 输入框最小高度 40px，长内容不被截断，圆角 10px
- [ ] 输入框有默认态、聚焦态、禁用态、错误态

### 校验与反馈
- [ ] 错误提示在字段下方，红色 12px
- [ ] 提交按钮在底部动作栏，lg 尺寸（48px）
- [ ] 提交中状态：按钮禁用 + 显示 Loading
- [ ] 提交失败：保留用户输入，显示错误原因
- [ ] 提交成功：有明确反馈（Toast / 成功页 / 自动返回）

### 底部动作栏
- [ ] 只有一个 Primary 主按钮，在右侧
- [ ] 取消/返回用 Secondary 或 Ghost
- [ ] 适配底部安全区

---

## 详情页检查

### 信息层级
- [ ] 基本信息在最上方的卡片中
- [ ] 状态标签 + 关键数据突出显示
- [ ] 辅助信息字号小一级，颜色浅一级

### 操作历史
- [ ] 用 Timeline 组件展示操作记录
- [ ] 每个时间节点有：时间、操作人、动作、状态变化
- [ ] 最新记录在最上方

### 附件
- [ ] 照片用 Photo Grid 九宫格展示
- [ ] 文件用列表行 + 文件图标展示
- [ ] 可点击预览

### 底部操作
- [ ] 主操作在底部动作栏右侧
- [ ] 操作数量合理（不超过 2 个按钮 + 最多 3 个图标）

---

## Bottom Sheet / 弹窗检查

- [ ] 顶部有 36×4px 把手条
- [ ] 最大高度 75vh，内部可滚动
- [ ] 底部按钮适配安全区
- [ ] 表单型 Sheet：有字段、有校验、有提交中/成功/失败态
- [ ] 提交中禁止点击蒙层关闭
- [ ] 失败后保留用户输入，不清空

---

## 自查不通过怎么办？

1. 先对照铁律卡（`DESIGN-RULES.md`）确认是不是硬伤
2. 查 `README-design.md` 的组件边界；本机设计资产可用时，再查对应组件规格和预览
3. 确实需要打破规则的，在代码注释里写明原因，并提 Review 时主动说明
