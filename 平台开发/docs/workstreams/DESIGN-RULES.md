# 设计铁律（10 条）

> 所有人做页面时必须遵守。违反即打回。
> 建议打印或钉在备忘录里，写代码前扫一眼。

---

## 颜色铁律

### 1. 业务类型不绑颜色
业务类型需要以标签表达时（巡检、工单、周检、水厂、监测站、试剂……），一律用**中性灰**（`--color-type-bg` + `--color-type-text`）。
颜色只用来表达**状态**，不用来区分"是什么"。

### 2. 状态只用 5 个语义色
| 颜色 | 语义 | 什么时候用 |
|------|------|-----------|
| 🟢 绿 success | 成功 / 正常 / 已完成 / 已通过 | 结果已确认且正向 |
| 🔵 蓝 info | 进行中 / 信息提示 | 过程中、系统通知 |
| 🟡 黄 notice | 提示级告警 | 告警四级体系中的最轻度 |
| 🟠 橙 warning | 等待用户动作 / 待审核 / 待审批 / 待补拍 / 待整改 | 需要人来处理 |
| 🔴 红 error | 异常 / 失败 / 危险 / 驳回 / 删除 | 出问题了或不可逆 |

**易错点**："待审核 / 待补拍 / 待整改" 是橙色（warning），不是蓝色（info）。
"运行中"是蓝色（info），不是绿色。

### 3. 主按钮统一蓝色
所有确认、提交、完成、通过、批准动作，按钮都是蓝色 Primary。
绿色只用来标状态，不做按钮。

### 4. 红色按钮仅用于破坏性操作
删除、驳回、退回等破坏性或高风险动作，才用红色描边按钮（Destructive）。
红色从不做填充主按钮。

### 5. 禁止卡片左侧彩色色条
不要用 `border-left` 给卡片加彩色侧边条来区分类型或状态。
状态用 Status Chip 表达，类型用灰底标签表达。

## 组件铁律

### 6. 优先复用既有组件
遇到新需求，先查 `README-design.md` 的组件清单和当前代码中的既有组件，能组合就不新增。
不为单一页面的一次性场景造通用组件。

### 7. 一个页面最多一个 Primary 主按钮
页面的核心操作只有一个，放在最突出的位置（底部动作栏右侧）。
其他动作一律用 Secondary / Text / Ghost。

### 8. 最小点击区域 44×44px
所有可点击元素的触控区域不小于 44px（iOS 标准）。
图标小按钮要扩大点击热区，不能只给 24px。

## 小程序铁律

### 9. 胶囊按钮不可覆盖
微信原生胶囊按钮（87×32px，距右 10px）无法去除、无法改样式。
任何自定义导航栏内容必须避让，标题不要强行居中。

### 10. TabBar 图标必须 PNG
小程序原生 TabBar 不支持 SVG。图标用 PNG（81×81px @2x 画布），
灰态 `#8E8E93`，选中态 `#007AFF`，线宽对齐现有图标。

## 违反了怎么办？

- **自己写代码时**：先自查这 10 条，有违反先改再提交
- **Review 别人时**：直接引用铁律编号（如"违反第 2 条，待审核应该用橙色"），减少无意义争论
- **不确定时**：查 `DESIGN-CHECKLIST.md` 或 `COMPONENT-DECISION-TREE.md`，再不确定就提出来讨论
