## 1. 领域使命

让站点身份、接收数据和双端展示形成可信闭环：数据能接收、解析、匹配、保存和展示，用户能区分“正常、需关注、暂无有效数据”，且系统不把仅收到报文误写成设备或仪器健康。

A 对本领域承担产品、后端、Web、小程序、数据适配、测试和后续路线责任，不只负责站点页面。

## 2. 核心链路

`站点档案/MN → 报文接收与原文证据 → 认证和站点匹配 → 规范化观测 → 监测查询/趋势 → Web 与小程序展示 → 异常事实提供给 C`

直接用户包括管理员、运维人员和查看监测结果的审核人员。完成标准必须覆盖数据进入前、等待首帧、已接收但未配置、正常展示、失败重试和无权限。

## 4. 不可变规则

- MN 是接入身份的第一精确依据，名称和别名只辅助匹配；少量未匹配不得阻断其他站点。
- 当前检测周期统一按 4 小时理解；分钟报文是传输频率，不得冒充检测周期。
- 接收状态、数据有效性、设备状态和仪器状态是不同事实；没有数据来源不得推断 RTU 或仪器健康。
- 原始报文证据与规范化观测分层保存，展示修正不得静默改写原始证据。
- 服务端负责站点范围和监测权限；前端隐藏不构成权限控制。
- 站点位置、名称等档案调整必须考虑 B 的签到/计划和 C 的告警/工单引用。
