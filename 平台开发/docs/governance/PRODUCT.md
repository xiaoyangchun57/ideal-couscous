# 产品职责：取舍、交接与审阅

仅在产品决策、正式委派、Review、验收裁决或冻结时使用。共同约束见根AGENTS.md，当前人员/树/权限见CURRENT_WORKING_AGREEMENT.md。

## 结果与路线

- 先区分现象、问题和方案。多阶段工作在原交接中说明端到端结果、必要输入/依赖、资源与时间限制、失败去向；不另造规划文档。
- 选择总成本最低的可行路径，成本包括实施、验证、失败恢复及剩余人工工作。已投入代码/交接不是维持原路线的理由。
- 同类阻断或原则失效再次出现时，继续返修前比较删步骤、解除依赖或换路线；写出选择及理由。纠偏始终对照同一个完整目标，不能随最近一句质疑来回扩大/放宽门禁。
- 审阅发现分为当前阶段阻断、后续阶段输入、非阻断披露项。阻断须有结果影响和最小解除条件；审阅者负责可走通的路径，而非只增加待办。辅助阶段失败不自动否定健康主链，总目标也不因局部成功关闭。

## 交接与写入权

- 产品定义问题、范围、验收和最终裁决，默认只读业务代码；当前发布执行者负责生产，产品不代操作。
- 正式切换执行者/写入权、实质变更范围或返回返修时，集中更新原自包含交接：目标、基线、允许/禁止范围、输入、验收、必要验证、停点、回传。其余连续反馈合并吸收，不逐条建文件。
- 开发交接放开发树，产品决策及发布证据放产品树；执行者不需跨树拼上下文。交接只保留当前指令，失效内容退出正文，历史留证据。
- 设计交接写清真实系统、页面及子页面责任、业务契约、文件权限和效果边界，视觉方案由设计决定；未授权不转移前端写入权。
- 用户转发时交付文件路径；不得代发或要求空接收回执。有消息授权时只传文件、类型、负责人和下一动作，不复制正文。接手以实际开始或回传为据，不靠文件更新猜测。

## Review与完成

- 一次检查声明范围内入口、直接消费者和受影响失败去向，集中给出必要问题。若后续发现遗漏，说明新证据、上一轮未覆盖的原因和本阶段影响，不自动全部阻断。
- 替身只证明其实际覆盖的行为；不可把阶段顺序通过当作真实消费者可用。已有有效结果复用，验证操作按VALIDATION.md选择。
- UI执行者按用户授权或当前交接确定，不能因流程默认创建独立任务。产品可审证据并裁决，不能把静态Review写成真实UI通过。
- 主线、阶段、写入者、交接或唯一下一动作实质变化才更新现有台账/检查点；不为每条反馈记一次。进度报告说实际结果、剩余工作和必要决策，不把文档更新次数当成果。
- 候选冻结须明确授权；固定提交和不可移动标签。当前版本/测试结果写本轮交接，不写入规范。进入发布后不修改冻结对象。

## 操作工具

正式边界操作使用water-quality-pm-loop技能的工具指引；同范围连续工作不重复启动完整流程。技能不替代本文件的产品判断，也不授权新增角色、扩大检查或操作生产。若技能与用户当前指令冲突，以用户指令为准；只修具体冲突，不顺手重建整套流程。
