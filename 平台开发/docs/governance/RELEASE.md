# 发布职责：当前候选到上线或恢复

仅发布准备、执行或恢复时读取。实际对象、允许操作、窗口、容量、业务输入和恢复依据来自当前自包含发布交接；历史执行卡不能自动复活授权。

- 发布执行者负责候选校验、授权打包、预检、备份、部署、验证和恢复，不修改冻结业务代码、标签或替代产品验收。发现候选业务问题交回产品裁决。
- 本地准备、打包、生产执行、Git推送、小程序发布和删除分别按已有明确授权执行；不得从监控、之前失败窗口或文件更新推断新授权。失败不自动重试，不重启正在运行的任务。
- 发布包从冻结标签生成，排除密钥、私有配置、测试数据、缓存和临时材料。恢复必须保留已接收的新写入，不能静默回旧库丢数据。
- 时间按本轮正式执行全程计，准备/传输/备份/验证/恢复不能换名排除；截止和恢复预留以当前合同为准。预算不冒充实测，不将工作移至后台绕过上限。
- 按阶段判断必要条件：切换所需恢复能力、数据完整性、必要配置不得省略；NAS、历史归档等辅助条件只在确属切换前提时阻断切换。分阶段完成必须保留未完责任和下一动作，不把业务在线当治理完成。
- 每个不变对象/状态和同一风险复用高成本验证结果。通常核对健康、必要的quick_check、备份状态、恢复清单/摘要/可读性；数据库重写、备份机制变化、矛盾证据或具体风险才做相称深查，不能因名字叫“迁移”就全库扫描。
- 发布后核对版本、挂载、必要迁移/quick_check、健康与本次业务烟测；不重复全套产品测试。没有制品或状态变化只重查失败/受影响项。
- 清理只按授权的精确对象。未知备份或retention条目保留并告警，不误删，也不因此令本来可完成的备份失败。逻辑删除量不能替代实际物理回收证据。
- 回传区分本地准备、上线、恢复和治理结果；健康检查不能代替业务，脚本成功不能代替总目标。保留NOT RUN和未完成事实。

工具操作使用water-quality-release-operator技能及其按需引用的执行说明，不在此复制命令。技能的默认示例不得覆盖当前合同的版本、截止、恢复预留或用户授权；需要调整机械操作时改唯一操作来源，不复制第二套。
