## 目标与边界

站点监测、试剂维护、站点档案和位置校准已经形成持续业务责任，不能继续分散在首页摘要、“我的”和深层页面。本轮将小程序底部导航调整为：

`首页｜巡检｜站点｜告警｜我的`

新 Tab 名称固定为“站点”，是移动端站点运维总入口；不命名为“站点监测”，也不做复杂数据驾驶舱。首页仅保留紧凑摘要和直达入口。“我的”不再保留重复的主要站点入口。

本轮不新增首页独立告警区。需要立即处理的告警继续进入“今日行动”并直达具体告警；全部告警由既有“告警”Tab 承担。

## 信息架构

### 1. 站点 Tab

- 页面一级模式固定为“站点 / 试剂”，进入时默认“站点”。二者属于同一个主 Tab，不再新增并列底部入口。
- 用户通过底部 Tab 返回时保留当前模式、范围和筛选；首页明确跳转时覆盖为目标模式。
- 页面标题使用“站点”。底部站点图标需提供普通态与选中态 PNG 资产，尺寸、线宽和颜色与现有四个 Tab 一致，五项并列时文字和安全区不得拥挤。

### 2. “站点”模式

- 默认显示“我负责”。管理员可切换“我负责 / 全部站点”；非管理员不出现全站入口。
- 管理员全站列表保留搜索，站点名称是第一识别层级，“我负责”标识帮助其从长列表中识别本人站点。
- 每项显示服务端给出的监测状态、最后报文/最后有效观测等关键时间及明确空态；实际因子最新值进入站点详情查看，列表不堆多项读数，也不得自行推导状态。
- “监测能力未启用”是中性能力状态，不是红色业务故障；网络失败才显示失败与重试。
- 点击站点进入既有站点详情：站点档案和位置校准仍在详情页，不在列表重复铺开。未来仪器状态与趋势也在站点域内扩展，但不纳入本次首版。
- 页面展示的是数据接收与有效观测状态，不能声称 RTU 在线、仪器正常或设备健康；现有数据源无法证明这些状态。

### 3. “试剂”模式

- 默认显示有权站点的待关注项目，不复制 Web 端完整试剂后台。
- 筛选固定为“全部 / 已过期 / 临期 / 低余量”，“全部”必须可单独清除状态筛选。
- “全部”包含库存关注项及待标定/标定失败项目；同一站点同一试剂只显示一条。已过期、低余量等原因可以同时成立，设计须保留多原因表达；标定状态作为同项子状态，不重复成多条。
- 每项以站点名称为第一层级，其后为试剂名称、状态、余量与单位、有效期或预计可用信息。内部编号不作为主要识别信息。
- 有维护权时提供“登记更换”和“完成标定”；无维护权时可查看但不出现伪动作。审核角色不能仅因可审核而获得试剂维护动作。
- 加载、刷新失败、无关注项、筛选无结果、无站点权限、长名称、`0` 和 `99+` 均需稳定呈现。

### 4. 两个维护 Sheet

设计必须覆盖真实操作界面，不能只画列表按钮。

**登记更换**

- 只读：站点、试剂、当前余量和计量单位。
- 输入：新余量、更换时间、预计可用天数；新批次号和备注按现有业务作为可选项。
- 必填、数值无效、提交中、服务端拒绝、成功刷新均有明确状态；失败保留输入，提交中禁止重复提交和关闭造成误解。
- 成功后该项进入“待标定”，列表状态随服务端结果刷新。

**完成标定**

- 只读：站点、试剂、更换信息。
- 输入：标样值、实测值、标定结果；不通过时必须选择“重新标定 / 报修”，备注可选。
- 同样覆盖必填错误、提交中、失败保留输入、成功刷新；不得把失败保存成成功视觉。

具体排版、控件和视觉层级由设计师按现有设计系统决定，但两个 Sheet 均须可在常见真机高度完整滚动并保持底部动作可达。

## 首页摘要

- “运维概览”仍位于“今日行动/今日作业包”之后，低于现场主任务层级。
- 站点摘要只统计本人负责站点：总数、正常、需关注、暂无有效数据。整行点击进入“站点”模式。
- 试剂摘要显示去重后的需处理数量，以及已过期、临期、低余量分布；三类原因可能重叠，分类数不要求相加等于需处理总数。不循环展示前两条具体试剂，不显示“另有 97 项”。整行点击进入“试剂”的“全部”关注列表。
- 站点和试剂摘要分别处理加载、刷新失败和中性未启用状态；局部失败不阻断首页其他内容。
- 两项应紧凑、整项可点击，不要求等宽等高，也不得形成卡片套卡片。

## 已确认接口事实

- 站点列表已有本人/全站范围、搜索、状态、关键时间与本人负责标识；设计不补造字段。
- 试剂现有接口需要开发补充分类计数、待标定/失败并集和安全写入后才能接线；设计节点可先按上述稳定语义命名。
- Tab 页面不能通过 URL 查询参数接收首页筛选；跨页目标由开发使用一次性应用状态处理。设计不得依赖 URL 参数。
- 登记更换、完成标定是脱离当前巡检计划也可发生的站点维护动作，不复用“计划 + 站点”限定的现场接口。
- 位置校准继续对所有现有角色开放，但只在有权站点详情中出现。

## 不可变边界

- 不改“今日行动、今日作业包、全部工单”的既有业务绑定；不新增首页告警卡或复杂监测面板。
- 不改变服务端权限、状态、数量和异常结论；不造测试数据，不用前端隐藏替代权限。
- 不把最新数据写成 RTU/仪器状态，不把传输频率写成检测周期。
