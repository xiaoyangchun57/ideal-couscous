## 1. 问题与目标

第二阶段已经具备接收、规范化、只读查询和启动安全门禁，但生产端点、业务站点、仪器及因子映射目前只能像测试一样直接写 SQL。该方式无法安全交给发布任务，也不能可靠复验或撤回。

本批只补一个**离线首站配置工具**：发布任务以后可在公网入口关闭、接收服务停止的条件下，先预检，再原子写入一个测试站点配置，并可核验或停用。它不是管理页面，也不是公网 API。

## 2. 产品契约

工具至少提供四个明确动作：

- `plan`：读取并校验配置，展示脱敏变更计划，数据库零写入；
- `apply`：在单一事务中创建首站端点、站点档案有效段和因子映射；
- `verify`：按运行时同一规则核对 schema、端点、站点关系、因子映射和凭据摘要，不写入；
- `disable`：仅停用指定端点，保留原始帧、观测、映射和历史证据。

必须满足：

1. 显式接收数据库路径和私有配置文件；默认不得指向固定或生产数据库。
2. 站点密码不进入命令行参数、配置文件、Git、普通日志或回传；只允许从标准输入或私有运行环境读取。HMAC pepper复用运行时 `SL651_CREDENTIAL_PEPPER`。
3. 写入前验证第二阶段完整 schema、目标业务站点存在、协议因子已定义、时间和周期合法、映射无重叠；存在权威资产记录时同时校验资产归属。
4. `apply` 对完全相同配置可重复执行且不新增记录；同站号异凭据、异站点或冲突有效段必须拒绝并保持零写入，不允许静默覆盖历史配置。
5. `disable` 必须要求明确确认和原因；再次执行为无副作用成功。不得删除或清空任何历史数据。
6. 输出只显示动作、业务站点、映射数量、配置指纹和结果；站号必须脱敏，不输出密码、HMAC、pepper、完整私有配置或原始报文。
7. 保存或校验失败必须返回可执行原因和非零退出码；不得出现部分端点已建、映射未建的中间状态。

## 7. 产品只读 Review 返修（2026-09-09）

### Review 结论

**本轮暂不通过。** 声明的自动测试可复现通过，但发布人员按当前命令操作仍可能写入无法认证或语义错误的配置，并可能把不可用端点误判为已就绪。只返修以下四项，不扩大原范围。

### 必须返修

1. **凭据输入必须与协议两字节字段一致。** 当前标准输入 `1234` 被保存为4个ASCII字节，而运行时帧密码是固定2个原始字节。明确将标准输入定义为恰好4位十六进制文本，解码为2字节后再计算HMAC；非法字符、长度和空输入均在写入前拒绝，输出仍不得泄露原文或摘要。
2. **协议因子不得被改写成错误业务指标。** 当前 `0311` 可配置成 `ph` 并成功写入，随后会把水温作为pH发布。已发布协议因子的 `business_metric` 应由权威定义派生，或仅允许与定义完全相同；未发布/无业务指标的因子不得由私有配置绕过发布边界。
3. **停用端点不得通过就绪核验。** 当前执行 `disable` 后，`verify` 仍返回 `verified`，`plan` 也返回 `ready`。两者必须明确返回不可用状态或非零失败，且不得静默重新启用；发布任务不能把已停用端点误认为可开放入口。
4. **只读动作不得创建数据库文件。** 当前对不存在路径执行 `plan` 会由 SQLite 创建空文件。所有动作连接前先要求目标是已存在的普通数据库文件；不存在或目录路径应失败且文件系统零副作用。

### 直接测试

- `0311 -> ph`、未发布因子强制指定业务指标均拒绝且零写入。
- 停用后 `plan`、`verify` 均不得返回 `ready/verified`。
- 对不存在路径运行四个动作均不得创建文件或目录。
- 复跑配置工具测试、迁移/存储/解析相邻21项、接收隔离13项、Python编译和定向差异检查。
