2T3 修复与已完成的验证（事实，非计划）

2.1 缺陷与修复

项内容
缺陷位置src/hooks/useUrlSyncedSearch.js → createUrlSearchDraftController().syncExternal(value)
缺陷行为选词（composition）进行中，若 URL 侧的值变化（其它模块/外部链接回写 q 参数、跨模块带入等），syncExternal 会直接 onDraft(value)，把正在选词的草稿覆盖掉 → 输入法候选被打断
修复在 syncExternal 增加 composing 守卫：选词期间挂起外部写入，最终值由 compositionEnd 时的用户输入决定
修复后语义选词期间：外部 URL 写入不覆盖草稿；选词结束：以用户选中文本提交并写入 URL；非选词期间：外部写入照旧生效（不破坏既有行为）

一个必须说清的自动化边界（已排查确定）：本应用所有搜索/筛选参数的写入统统使用 replace: true，因此"用浏览器后退"在本机实际会退到另一个文档条目并触发整页重载（实测：整个 React 树连侧边栏一起被重建），那不是"URL 回写"，也无法用于验证该 hook。所以自动化的回写触发必须是同文档的 URL 变化（history.replaceState + popstate），这正对应真实风险路径（其它模块 / 外部链接回写同一 q 参数）。

B2 进阶（可选）：亲眼看到"选词期间被 URL 回写覆盖"这条风险

人工无法在候选窗打开时去点地址栏（一点就失焦）。下面的做法可以：先在控制台安排一次延迟回写，再在倒计时内开始打字。

1
在页面上打开开发者工具控制台（F12）
先切到"站点搜索"页面并确保地址栏是 http://127.0.0.1:5174/sites。
2
粘贴并执行下面的脚本（安排 6 秒后回写 q 参数）
setTimeout(() => {
  const url = new URL(location.href);
  url.searchParams.set('q', 'gamma');          // 模拟其它模块回写同一参数
  window.history.replaceState(window.history.state, '', url);
  window.dispatchEvent(new PopStateEvent('popstate', { state: window.history.state }));
  console.log('[evidence] q 已回写为 gamma');
}, 6000);
3
在 6 秒内完成：点搜索框 → 打拼音 zhong → 让候选窗保持打开
盯着输入框等着倒计时结束（控制台会打印 [evidence] q 已回写为 gamma）。
4
截图 ③ 并判定
保存为 B2-选词期间URL回写-草稿未被覆盖.png。
合格：回写发生后，输入框仍是拼音 zhong、候选窗仍在（地址栏已是 q=gamma）。
不合格：输入框变成 gamma 或被清空、候选窗消失。

B4 故障排查：搜索框里出现"重复累积"的怪串

症状：输入框里不是干净的拼音，而是每一键的前缀快照被首尾拼接 —— 例如打 baiquan 却显示 bbabaibai'qbai'qbai'qubai'q（b+ba+bai+bai'q+…）。这是 composition 被反复提前打断的特征，属修复前的缺陷表现，不要当成新缺陷。

排查项判断与处置
① 页面是否修复后的代码dev server 停过之后，已打开的标签页会成为"孤儿"（HMR 断开、代码冻结在旧版本），必须重新加载页面。校验命令（F12 控制台）：
fetch('/src/hooks/useUrlSyncedSearch.js').then(r=>r.text()).then(t=>console.log(t.includes('composing) return')?'修复版':'旧版'))
② 浏览器扩展干扰划词/翻译类扩展会在输入框上做手脚。用 InPrivate 窗口（Ctrl + Shift + N）打开同一地址重测；InPrivate 下正常 → 主配置文件存在扩展或缓存问题
③ 是否"安装为应用"的窗口Edge「安装此站点为应用」打开的窗口没有地址栏：既容易误判，也拍不出合规截图。请改用普通标签页
④ 输入法侧本机只安装了微软拼音（zh-Hans-CN），真机复测正常，可排除输入法本身
本机真机复测结论（2026-09-23）：真实 Edge 窗口 + 真实微软拼音 + 程序注入的真实键盘事件，逐键输入 zhong → 输入框干净递进（z→zh→zho→zhon→zhong），isComposing=true 全程保持，地址栏全程无 q=；上屏后才写入。→ 修复后代码在真实 IME 路径下正确，"累积串"只出现在未重新加载旧代码的页面上。
